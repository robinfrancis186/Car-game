# Bounded native acceptance after publication

Parent/test owner controls any permitted browser window. Preserve the user's existing profile, balance, owned cars, upgrades and Story progression. Do not reset, top up, buy, unlock or deliberately bank test rewards. Restore the original viewport and return controls at the agreed deadline.

## Priority checks
1. Load the exact published V14 build. Record URL/build identity, viewport and console errors. Confirm the actual 3D car/world is present; the CSS preview's neutral hero regions are not evidence of production composition.
2. Home → Play: open/close Change car; reach first/last option without it permanently covering the hero. Keep an already-owned car selected. Inspect both routes without starting a reward-bearing test race unless needed.
3. Garage → Owned/Shop → locked Car details: reach first/last card and return. Inspect existing upgrade rows and the last Boost action without purchasing. Confirm price, owned/locked/selected states and existing balance are consistent.
4. Help at top, mid-scroll and Credits: heading/Close remain visible. Exercise pointer Close, Escape, Tab/Shift+Tab and focus restoration. Toggle Sound in Help and restore its initial state. Verify no accidental gameplay shortcut on a disclosure or select.
5. Start a brief drive, Pause → Help → Sound toggle → Close: remain paused, time/position unchanged, return focus to an appropriate control. Resume and confirm controls still function. Do not treat AudioContext/label state as proof of audible sound quality.
6. Inspect driving HUD at the original viewport and, if permitted, 568×320 landscape/390×844 compact emulation: speed does not overlap Camera/Pause, controls remain reachable, and text is readable against the actual road. Emulation is not physical-phone acceptance.
7. If time permits, Story briefing → intro → Skip → Pause → Home. Do not advance or claim later chapter/result acceptance from staged preview screenshots.

Record untested states explicitly. Results, failures, protected saves and loading errors are covered by isolated CSS/source fixtures, not falsely reported as naturally reached native states. Point FPS values are not sustained performance benchmarks. End at a safe menu or paused state and restore original audio/viewport preferences.
